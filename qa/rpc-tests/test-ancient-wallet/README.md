# Zcashd "ancient" regtest test wallet fixture

Test fixture for `qa/rpc-tests/zcashd_key_import_ancient.py`.

A pre-Sapling, **HD-seedless** zcashd `wallet.dat`: a transparent-only
(plus Sprout) wallet with **no `hdseed` and no mnemonic**, generated by
the pre-Sapling zcashd binary **v1.1.1**. Unlike the modern
`../test-wallet` fixture (which carries an HD seed and spans all network
upgrades), this wallet exercises zallet's seedless import path
(<https://github.com/zcash/wallet/issues/384>), where the migration mints
a fresh recovery seed to back the legacy transparent account.

## Status: the test runs in CI but is expected to fail

The fixture is real and committed, and `zcashd_key_import_ancient.py`
runs as part of the normal test suite. It will fail until the migration
stack can consume a pre-Sapling wallet:

1. **`zewif-zcashd` cannot parse pre-Sapling `wallet.dat`**
   (<https://github.com/zcash/zewif-zcashd/issues/14>). Its parser
   unconditionally requires the `networkinfo` and
   `orchard_note_commitment_tree` records (both introduced in a later
   `wallet.dat` version; ZIP 400 "version 5"). A v1.1.1 wallet has
   neither, so `migrate-zcashd-wallet` aborts with
   `An error occurred in extracting wallet data ... 'Getting 'networkinfo' record'`
   before any keys are imported. Verified with `db_dump -p wallet.dat`:
   the file contains `key`, `keymeta`, `pool`, `watchs`, `zkey`, `vkey`,
   `witnesscachesize`, `version`, `minversion`, etc., but no
   `networkinfo`, `orchard_note_commitment_tree`, `hdseed`, or
   `mnemonicphrase`.
2. **zallet's seedless legacy-account logic (wallet#384)** is not yet
   implemented. (An earlier implementation on a zallet branch predated
   the import-stack rewrite in zallet PR #571 and no longer exists.) The
   work is now tracked at <https://github.com/zcash/zallet/issues/739>:
   mint a fresh mnemonic and re-point the legacy `zcashd` transparent
   account (the "bucket of funds") at it. Related hardening is tracked
   at <https://github.com/zcash/zallet/issues/740> — the migration will
   fail loudly on empty/partial imports — which this test should
   tolerate (and ideally assert) once it lands.

The test goes green once both land (plus the zallet dependency bump
wiring them together) and the `zallet` binary under test is built with
the `zcashd-import` feature.

## Contents

The pre-Sapling binary (v1.1.1) only supports a subset of the import
RPCs, so the per-phase `imported_keys` carry:

- `transparent_privkey` — `importprivkey` (spendable)
- `transparent_watchonly` — `importaddress <addr>` (watch-only-by-hash;
  the test records this as SKIPPED — zallet does not support importing
  watch-only addresses by script-hash alone)
- `sprout_spending` / `sprout_viewing` — `z_importkey` /
  `z_importviewingkey` (not asserted; zallet does not support Sprout)

The fixture manifests contain **no** `transparent_pubkey`
(`importpubkey`) or `transparent_p2sh` (`importaddress <redeemScript>`)
entries. Those import paths are covered by `../test-wallet` /
`zcashd_key_import.py`.

### Why no `importpubkey` / P2SH `importaddress` entries

zcashd v1.1.1 supports neither import (verified against its source): it
has no `importpubkey` RPC at all, and its `importaddress` takes only
`(address|script, label, rescan)` — no P2SH flag. The wallet builder's
version gate (`qa/zcash/wallet-builder/lib/key_imports.py`, and its
README / `versions.json`) enables both at zcashd >= v1.1; that gate is
simply wrong, and during generation both import attempts failed
silently inside the builder's per-import `try`/`except` handlers. The
wallet builder lives in the now-archived zcash/zcash repository and
cannot be fixed there; the gate can only be corrected in a fork or
successor repository.

The wallet also contains mined transparent coinbase UTXOs and Sprout
notes. `full_manifest.json` + `manifests/phase_NN_*.json` follow the same
schema as `../test-wallet`.

## Regenerating

1. In the wallet builder, build the image and the ancient wallet:
   `make build && make ancient && make extract`. Record the builder
   commit hash (`git -C <zcash checkout> describe --always`) — without it
   the fixture is not reproducible.
2. Copy `output/wallet.dat`, `output/full_manifest.json`, and
   `output/manifests/` into this directory, overwriting the existing
   files, and update the **Source** section above.
3. Run the test to confirm the fixture decodes cleanly (requires a
   `zallet` with both the seedless import path and the `zcashd-import`
   feature, plus the zewif-zcashd fix above):
   `python3 qa/rpc-tests/zcashd_key_import_ancient.py`.
